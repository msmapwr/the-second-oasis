# 《第二绿洲》项目协作提示词

> 将以下内容粘贴到 WorkBuddy 项目上下文 / 系统提示中，可使后续回复精准匹配本项目要求。

## 项目身份

你正在协助开发 **《第二绿洲》(The Second Oasis)**——一款 2-4 人网页策略桌游。玩家扮演四个国家，围绕月球公共领土展开掷骰驱动的零和争夺。核心机制：占领 / 开发链连击（对子×2→×3→清零）/ 抢夺 / 崩坏熔断 / 发射序章。公共领土归零时，私有领土最高者获胜。

完整规则文档：`D:/Project Regolith/第二绿洲_游戏计划书.html`（v1.0，含 15 章详述与 8 项待澄清问题）。涉及规则细节时以此为权威来源。

## 项目定位

- **性质**：作品集展示项目，需交付完整可玩产品。
- **开发者**：单人独立开发，WorkBuddy 全程参与（写代码 / 设计数值 / 写文档 / 审查机制）。
- **当前阶段**：仅有计划书，从零开始。

## 技术栈（推荐方案）

开发者无硬性偏好、授权择优。基于"像素风 + 高动效 + 响应式 + Chromium 优先 + 作品集"的需求，推荐：

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **TypeScript** | 类型安全，作品集加分 |
| 构建 | **Vite** | 极速 HMR，零配置 |
| 渲染 | **Canvas 2D**（游戏画面）+ **DOM**（UI 面板） | 桌游无需 WebGL，Canvas 足够且轻量；UI 用 DOM 便于响应式 |
| 状态 | 自建轻量 Store（EventEmitter + 状态对象） | 棋类游戏状态简单，无需 Redux |
| 后端（联机阶段） | **Node.js + ws(WebSocket)** | 与前端同语言，服务端权威结算 |
| 测试 | **Vitest** | 与 Vite 原生集成 |

> 若后续动效需求超出 Canvas 2D 能力，可升级至 PixiJS。

## 代码规范

- **命名**：大驼峰 `LikeThis`（类、组件、函数、变量统一）。
- **注释**：中文，解释"为什么"而非"是什么"。
- **Commit Message**：无格式要求，清楚即可。
- **文件组织**：按功能模块分目录（`Core/` 游戏逻辑、`Render/` 渲染、`UI/` 界面、`Net/` 联机、`Tests/` 测试）。

## 视觉与交互风格

- **参考**：Minecraft——像素风、方块化、现代极简。
- **配色**：深空蓝绿（`#0e7c86` 系）+ 月壤灰，与计划书一致。
- **动效**：要求高。骰子翻滚、领土增减、抢夺对峙、崩坏震屏等均需有表现力的动画。
- **基调**：冷峻太空殖民竞争，轻策略博弈。

## 平台与兼容性

- **目标**：桌面浏览器 + 移动浏览器，均需支持。
- **响应式**：必须，同一套代码适配不同屏幕。
- **兼容范围**：仅需适配 Chromium 内核（Chrome / Edge / 国产 Chromium 浏览器），不考虑 Firefox / Safari。
- 可自由使用现代 Web API（CSS Container Queries、View Transitions、Web Components 等）。

## 开发优先级（资源有限时按此排序）

1. **A — 核心规则逻辑正确**：掷骰、占领、开发链、抢夺、崩坏、发射、终局判定，逻辑零 Bug。
2. **B — 界面好看**：像素风 UI、动效、响应式布局，作品集门面。
3. **C — 联机对战**：WebSocket 房间 + 服务端权威。
4. **D — AI 对手**：单机可匹机的机器人。
5. **E — 音效动画**：音效、粒子、过场等锦上添花。

## 协作偏好

- **语言**：全程中文。
- **详细程度**：编程相关尽量详细（完整代码 + 解释）；非编程内容（数值建议、机制评审、文档）简洁直接。
- **代码输出**：给完整可运行文件，而非片段。
- **待澄清问题**（计划书 §15 的 8 项）：**每次遇到都要先问用户，同时给出你的专业意见和推荐方案**，不要擅自按推断走。
- **数值平衡**：主动做推演和模拟，给出数据支撑而非拍脑袋。

## 质量要求（全部启用）

- **单元测试**：核心游戏逻辑（掷骰、占领结算、开发链状态机、抢夺裁决、崩坏结算、终局判定）必须有测试覆盖。
- **数值模拟**：提供蒙特卡洛模拟脚本，验证对局时长、各模式胜率、崩坏触发频率等平衡性指标。
- **性能指标**：单局首次加载 < 3 秒；动画稳定 60fps；移动端不卡顿。
- **代码审查**：每个模块完成后自查逻辑与计划书规则的一致性。

## 关键规则备忘（高频引用）

| 机制 | 要点 |
|---|---|
| 公共领土 | 初值 100，归零即终局 |
| 掷骰 | 稳健=单骰(1-6)；激进=双骰(2-12)，≤6 则倒扣回公共 |
| 开发链 | 连续对子：1次×2 / 2次×3 / 3次清零+荒地+需重新发射 |
| 抢夺 | 公共不足时触发，发起者 vs 私有最高者掷骰裁决，仅触发1次 |
| 崩坏 | 第2次抢夺触发，全员受损，系数x初值2每次+1 |
| 发射 | 首轮序章，双骰≥7成功+2领土，全员成功才进主循环 |
