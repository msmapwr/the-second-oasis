Gameplay & Balance Optimization Notes

状态建议稿 · 可选变体

1审阅结论

一句话：A 优先级核心规则已经扎实、可玩，且数值平衡；下一步优化应放在决策空间、玩家交互与落后追赶上，而不是推翻现有规则。

读完《第二绿洲》计划书 v1.1 并核对 src/Core/ 的实现后，我认为当前系统有两个很强的乐趣支点：

  • 开发链（连击）：玩家在连续对子的“再博一次”与“见好就收”之间做决策，情感曲线清晰。
  • 公共池归零：零和竞争的张力随着公共领土减少而加速，配合抢夺 / 崩坏制造了戏剧化反转。

同时发现四个可进一步打磨的杠杆：

  1. 落后追赶：领先者可以切“稳健”或“不开发”龟缩到终局，落后者缺少可控的反击手段。
  2. 交互次数：整局只有一次“抢夺”直接指向玩家，之后全是全局随机的“崩坏”。
  3. AI 性格出口：Avenger 的复仇维度没有对应的规则机制，只能影响评分倾向。
  4. 终局节奏：公共池在 20 以下时，游戏可能拖尾，也可能被一次崩坏直接带走。
建议方向把优化做成“v1.2 变体包”，通过 GameConfig 开关控制。这样作品集既保留 v1.1 的权威规则，又能展示更丰富的策略层。

3关键痛点

3.1 领先者可“龟缩”

一旦某玩家建立 5–10 点的私有优势，他可以直接切“稳健”甚至“不开发” conservative strategy，因为：

  • 稳健不会倒扣，不会触发开发过度。
  • 不开发不消耗公共池，反而延缓终局，让对手先触发崩坏。
  • 除了一次抢夺外，没有针对领先者的直接打击。

这会导致终局变成“谁先手谁稳赢”或“谁先崩坏谁倒霉”，决策空间收窄。

3.2 一次抢夺后的交互真空

抢夺是一个非常强的再分配机制：失败方损失最多 m2，胜利方获得 m2 - r，公共回流 r。但它只触发一次。之后所有溢出都进入全局随机的崩坏，玩家之间不再互相点名，社交张力下降。

3.3 AI 的“复仇”维度没有规则出口

AI 性格中的 Vengefulness 目前只能影响评分权重，没有真正的复仇动作。人类玩家也缺少“被搞了就要搞回来”的通道，导致情感曲线缺少闭环。

3.4 终局节奏两极化

当公共池 ≤ 20 时：

  • 如果所有玩家都稳健，可能需要 5–10 回合才能归零，拖尾。
  • 如果有人激进溢出，一次崩坏系数 x 可能直接把公共扣到 0，胜负由一次随机事件决定。

需要一个更稳定的“终局加速器”。

4推荐机制

下面四个机制按“实现复杂度从低到高”排列，均可通过 GameConfig 开关启用。建议先组合前三个作为 v1.2 标准变体包。

4.1 公敌税（Leader Tax）—— 解决“龟缩”

机制定位

每轮结束时，私有领土严格领先的玩家向公共池缴纳“外交孤立税”。领先不是白给的，而是有维护成本。

玩家体验目标

“我终于追上来了——但这也意味着我成了靶子。”让领先者不能无脑稳健，同时给落后者一个自动化的追赶窗口。

输入 / 输出

输入：每轮结束后的 Snapshot。
输出：领先者 Private -= Tax，Public += Tax（严格零和）。

// 每轮结束结算（仅当存在唯一领先者时） Leader = argmax(Private_i) Tax = 1 // [PLACEHOLDER] 基础值，建议按领先幅度缩放 Private_Leader' = max(0, Private_Leader - Tax) Public' = Public + (Private_Leader - Private_Leader')
边界情况
  • 多人并列最高：不征税（避免随机 tie-break 被感觉为不公平）。
  • 领先者私有为 0：税额为 0，不反向扣。
  • 征税后公共可能超过 100？不会，因为税只来自玩家私有，总量守恒。
调参杠杆

LeaderTaxBase（基础税额，默认 1）、LeaderTaxScale（是否按领先幅度缩放，如每领先 10 点 +1）。

实现提示

在 GameState 的回合推进末尾或新增 EndOfRoundPhase 中调用；每轮只触发一次，记录到 TurnHistory。

4.2 顺位轮换（Rotating Start）—— 解决先手优势

机制定位

每轮的起始玩家按轮次轮换，而不是永远 0 号玩家先手。

玩家体验目标

“我这次最后行动，但下一轮我先手。”让座位顺序不再决定长期胜率。

// 每轮开始 FirstPlayer = RoundIndex % PlayerCount CurrentPlayer = FirstPlayer
边界情况

发射阶段和重新发射阶段仍以自然座位顺序处理，避免打乱“谁还没发射”的逻辑。

实现提示

在 GameState 中增加 _RoundIndex，每轮完整循环后 +1。

4.3 枯竭冲刺（Scarcity Sprint）—— 解决终局拖尾 / 随机

机制定位

当公共池进入最后阶段，所有资源争夺效率提升，终局被强制加速。

玩家体验目标

“池子快干了，所有人都在疯抢。”让终局更有仪式感，而不是慢慢磨或突然暴毙。

// 当公共池低于阈值时进入冲刺阶段 SprintThreshold = 30 SprintBonus = 2 if Public <= SprintThreshold: RawGain' = RawGain + SprintBonus // 不开发模式下不生效，因为 RawGain = 0
边界情况
  • 冲刺奖励只加成 RawGain，仍然受开发链倍率影响，因此连击对子在冲刺期更恐怖。
  • 如果 RawGain 为负（激进倒扣），冲刺奖励是否仍加？建议“只加正收益，负收益不变”，否则倒扣会变得更疼。
调参杠杆

SprintThreshold（默认 30）、SprintBonus��默认 2）。可在蒙特卡洛中测试 20/25/30 三个阈值。

4.4 复仇突袭（Revenge Raid）—— 解决交互与 AI 出口

机制定位

被抢夺的玩家获得一枚“复仇令牌”，可在后续任一回合消耗它发动一次针对抢夺者的突袭。

玩家体验目标

“你抢我？我记着。”给 Avenger 性格和人类玩家一个情感闭环，同时把交互从一次扩展到全局。

// 复仇令牌获取 if 玩家是抢夺中的低者（或崩坏中损失最大者）: RevengeToken = 1 // 发动突袭（替代普通模式，占用一回合） Target = 默认抢夺者 / 崩坏发起者（人类可手动选择任意玩家） Roll = 1 颗骰子（1~6） if Roll >= 4: // [PLACEHOLDER] 成功率阈值 Steal = Roll - 2 // 1~4 Target.Private -= min(Steal, Target.Private) Self.Private += Steal // 零和转移 else: Self.Private -= 1 // 失败惩罚，回归公共池 RevengeToken = 0
边界情况
  • 令牌最多 1 枚；再次被抢不叠加。
  • 目标私有不足时，只扣除实际可用部分。
  • 目标处于荒地 / 需重新发射时仍可被突袭，但收益可能为 0。
  • 若目标已经离开游戏（不可能，因为无淘汰），忽略。
调参杠杆

RevengeSuccessThreshold（成功阈值，默认 4）、RevengeFailureCost（失败惩罚，默认 1）、RevengeStealFormula（Roll-2 / Roll / Roll/2）。

实现提示

需要新增 DiceMode.Revenge 和 RevengeToken 字段；AI 的 DecideMode 中已支持性格权重，可直接接入。

6推荐组合：v1.2 标准变体包

如果希望一次只改一个“最小可用变体”，建议启用以下组合：

公敌税 顺位轮换 枯竭冲刺

理由：

  • 公敌税直接削弱龟缩，让落后者有被动追赶。
  • 顺位轮换几乎零风险，立即平滑先手优势。
  • 枯竭冲刺把随机崩坏转化为“可预期的终局加速器”，玩家可以提前几回合开始规划。

复仇突袭作为可选扩展，建议放在第二批实现。它引入新的 UI（选择目标、复仇令牌图标）和新的模式，收益很高但实现成本也更高。

7下一步：验证与实现

  1. 扩展蒙特卡洛模拟：让 MonteCarloSimulation 支持策略混合（例如 30% 稳健 / 70% 激进），并加入新机制的开关。对比变体包与 v1.1 的胜率方差、平均回合。
  2. 在 GameConfig 中新增变体开关，如 EnableLeaderTax、EnableRotatingStart、EnableScarcitySprint，保证旧规则可一键回归。
  3. AI 适配：让 Evaluator 在计算三种模式时，把 Leader Tax、Revenge Token、Sprint Bonus 纳入评分，确保 AI 也能利用新机制。
  4. 三人试玩：每改完一个变量就试玩 3–5 局，记录“领先者是否还能龟缩”“终局是否更有仪式感”。
不要一次性全改建议先实现“顺位轮换 + 枯竭冲刺”（低风险），跑测试通过后再加“公敌税”，最后才是“复仇突袭”。
