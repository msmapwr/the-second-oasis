# 《第二绿洲》v1.4.0 详细实施计划

> 版本定位：观战 + 回放系统  
> 依赖：v1.4.1 联机消息协议扩展（手牌可见性、房间列表、卡牌事件广播）  
> 目标：在不动 Core 规则的前提下，落地观战、录制、回放、导出四项功能。
>
> 备注：当前代码基线（v1.3.2）已经实现 USE_CARD / CARD_RESULT / HAND_UPDATE 等联机卡牌消息，以及观战者可见手牌的服务端广播。v1.4.0 可以复用这些成果，只需要补「房间列表」、「HAND_REVEAL 全手牌」、「回放录制与面板」三项增量工作。

---

## 1. 总体架构

新增三条纵向能力，全部挂在现有 `GameStore` / `NetworkGameStore` / WebSocket 消息体系上：

| 能力 | 核心模块                             | 与现有系统关系                                 |
| -- | -------------------------------- | --------------------------------------- |
| 观战 | `SpectatorGameStore` + 大厅房间列表    | 复用 `GameStageView` 的 spectator 模式，只读不操作 |
| 录制 | `ReplayRecorder` + `ReplayStore` | 订阅 `GameStore` 事件流，写入 IndexedDB         |
| 回放 | `ReplayEngine` + `ReplayPlayer`  | 用同一颗种子重建 `GameStore`，按事件逐步推进            |
| 导出 | `ReplaySerializer`               | JSON + 可选 gzip，文件下载 / 文件选择导入            |

关键原则：

- 服务端保持唯一权威；观战者只接收广播，不发送任何改变状态的消息。
- 回放基于“初始状态 + 事件日志”而非逐帧快照，保证数据量可控。
- 所有新增类型都走 TypeScript 严格类型，不放宽 `strict`。

## 3. 联机观战模式

### 3.1 服务端流程

1. 大厅通过 `GET_ROOM_LIST` 拉取所有 `Playing` 房间。
2. 用户点击「观战」→ 发送 `SPECTATE_ROOM`。
3. `RoomManager.AddSpectator` 校验房间存在且已开始。
4. 返回 `SPECTATOR_JOINED`，包含当前完整 `snapshot` 与所有玩家手牌。
5. 后续所有 `TURN_RESULT` / `LAUNCH_RESULT` / `TIEBREAKER_RESULT` / `CARD_RESULT` / `HAND_REVEAL` 自动广播给观战者。
6. 观战者 WebSocket 关闭时，只从 `Spectators` 移除，不触发 AI 托管。

### 3.2 客户端 `SpectatorGameStore`

新建 `src/Net/SpectatorGameStore.ts`，实现 `IGameStore`：

- 内部持有 `NetworkGameStore` 实例，转发只读属性与事件。
- `MyPlayerId = -1`，`IsSpectator = true`。
- 所有写操作（`Start`、`PlayTurn`、`AttemptLaunch` 等）直接抛错。
- 维护 `_SpectatorHands: Map<PlayerId, CardInstance[]>`，通过 `HAND_REVEAL` 更新。
- `GetCardHand` 返回缓存的完整手牌，覆盖父类行为。

### 3.3 大厅 UI

`MultiplayerLobby` 增加阶段 1.5「房间列表」：

- 顶部增加「刷新房间列表」按钮，轮询或手动拉取。
- 列表项显示：房间码、房主、人数 `playerCount/maxPlayers`、观战人数。
- 每个 `Playing` 房间右侧显示「观战」按钮；`Lobby` 房间显示「加入」。
- 选择观战后走 `LobbyClient.SpectateRoom()`，进入对局界面。

### 3.4 对局界面适配

`GameStageViewConfig` 增加 `IsSpectator?: boolean`：

- `true` 时隐藏 `ControlConsole`（或渲染为只读状态条）。
- `CardHandView` 使用 `Mode = 'spectator'`，显示全部玩家手牌正面。
- 底部显示「观战中 · SPECTATOR」水印。

`AppController._PlayGame` 支持 `ExistingStore` 为 `SpectatorGameStore`：

- 不创建 `AIDirector`。
- 不调用 `Input.BindKeyboard`。
- 正常接收广播并渲染动画。

## 4. 对局回放录制

### 4.1 录制器 `ReplayRecorder`

新建 `src/Store/ReplayRecorder.ts`：

- 订阅 `GameStore` 事件：`Launch`、`Turn`、`Tiebreaker`、`CardUsed`、`GameOver`、`PhaseChange`、`RoundChange`。
- 每个事件序列化为 `ReplayEvent`：

```ts
type ReplayEvent =
  | { type: 'Launch'; payload: LaunchResult }
  | { type: 'Turn'; payload: TurnResult }
  | { type: 'Tiebreaker'; payload: TiebreakerRound }
  | { type: 'CardUsed'; payload: CardPlayedRecord }
  | { type: 'GameOver'; payload: GameResult }
  | { type: 'PhaseChange'; payload: { from: GamePhase; to: GamePhase } }
  | { type: 'RoundChange'; payload: { roundIndex: number; firstPlayerIndex: PlayerId } };
```

- 记录 `ReplayHeader`：
  - `version: '1.0'`
  - `seed`、`playerCount`、`variant`（传统/现代）
  - `playerConfigs`（名字、颜色、是否 AI）
  - `createdAt`、`finalResult`（终局后回填）
- 对本地对局：在 `AppController._PlayGame` 开局时挂载到 `Store`。
- 对联机对局：在 `NetworkGameStore` 收到事件时同步记录（客户端录制，避免服务端存储压力）。

### 4.2 卡牌事件补全

当前 `GameStore.UseCard` 只触发 `CardUsed: { CardType }`，信息不足以回放。  
需要把 `CardPlayedRecord` 塞进事件：

```ts
this.Emit('CardUsed', {
  Record: Result,        // 新增
  CardType: Result.CardType,
  Snapshot: this._State.Snapshot,
});
```

对应调整 `StoreEvents.CardUsed` 类型。

### 4.3 存储 `ReplayStore`

重写 `src/Store/ReplayStore.ts`：

- 使用 IndexedDB（`second-oasis-replays`），对象存储 `replays`。
- 存储结构：

```ts
interface StoredReplay {
  id: string;
  version: string;
  createdAt: number;
  header: ReplayHeader;
  events: ReplayEvent[];
  compressed: boolean;
}
```

- 列表元数据单独缓存到 localStorage 用于快速展示。
- 上限策略：最多 50 条或 100MB，超出时按时间淘汰最旧。
- 压缩：写入前尝试 `CompressionStream('gzip')` 压缩 `events` 的 JSON 字符串；读取时解压。不支持时回退原始 JSON。

## 5. 回放面板

### 5.1 回放引擎 `ReplayEngine`

新建 `src/Store/ReplayEngine.ts`：

- 用 `ReplayHeader` 创建本地 `GameStore`（与对局同一配置）。
- 维护 `currentIndex`，表示已应用的事件数量。
- 方法：
  - `StepForward()`：应用下一个事件。
  - `StepBackward()`：`Reset()` 后重新应用到 `currentIndex - 1`。
  - `JumpTo(index)`：同上，用于进度条拖拽。
  - `Play(speed: 1 | 2 | 4)`：按速度自动 `StepForward`，到结尾暂停。
  - `Pause()`。
- 应用事件时，直接调用 `GameStore` 的同步方法（`AttemptLaunch`、`PlayTurn`、`RunTiebreaker`、`UseCard`），因为种子相同，结果与录制一致。
- 对外暴露 `IGameStore` 接口，并把内部 `GameStore` 传给 `AnimationCoordinator`。

### 5.2 回放 UI `ReplayPlayer`

新建 `src/UI/Components/ReplayPlayer.ts`：

- 复用 `GameStageView`（`Mode='spectator'`），显示棋盘、席位、手牌。
- 底部固定控制条：
  - 上一回合 / 播放·暂停 / 下一回合
  - 进度条（当前事件 / 总事件）
  - 速度切换 1x / 2x / 4x
  - 关闭回放
- 播放时根据事件类型触发对应动画：
  - `Launch` / `Turn` / `Tiebreaker` → `DiceStage.Play`
  - `Collapse` → 震屏
  - `Robbery` → 席位闪烁

### 5.3 入口

- 主菜单 `MainMenu` 控制台增加「回放 REPLAYS」按钮，打开 `ReplayListPanel`。
- `ReplayListPanel` 列出已保存回放，支持：播放、删除、导出。
- 终局界面 `GameOverScreen` 增加「保存回放」按钮：
  - 点击后把当前 `ReplayRecorder` 内容写入 `ReplayStore`。
  - 显示「已保存」提示，并给出「观看回放」快捷入口。

## 6. 回放数据导出 / 导入

### 6.1 导出

`ReplaySerializer.Export(replay: StoredReplay)`：

1. 序列化为 JSON。
2. 如果浏览器支持 `CompressionStream`，gzip 压缩；否则保留原始 JSON。
3. 生成 Blob，文件名：`second-oasis-replay-${date}-${roomCode}.tso.json`。
4. 通过临时 `<a download>` 触发下载。

### 6.2 导入

`ReplaySerializer.Import(file: File)`：

1. 读取文本 / 解压（检测 magic bytes）。
2. JSON 解析。
3. 校验：
   - `version` 匹配当前支持版本。
   - `header.seed`、`header.playerCount`、`header.variant` 合法。
   - `events` 非空且第一条为 `PhaseChange` 或 `Launch`。
4. 返回 `StoredReplay`，直接交给 `ReplayEngine` 播放。

## 7. 容量与性能策略

| 风险             | 方案                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------- |
| 长对局事件日志过大      | 1. 仅记录事件，不记录每帧快照；2. gzip 压缩；3. 每 50 回合插入一个 `Keyframe` 事件（完整 `TerritorySnapshot`），便于快速跳转。 |
| IndexedDB 容量上限 | 设置 50 条 / 100MB 上限，LRU 淘汰。                                                               |
| 回放跳转卡顿         | `JumpTo` 时 `Reset()` 后重播到目标位置；现代设备 100 回合重播 < 50ms，可接受。若未来出现 500+ 回合，再优化为基于关键帧二分查找。      |
| 观战者手牌同步延迟      | 服务端在手牌变化后立刻广播 `HAND_REVEAL`，不合并；消息体很小。                                                   |

## 9. 测试计划

### 9.1 单元测试

- `ReplayEngine.test.ts`：给定录制事件，逐步播放后终局状态与原对局一致。
- `ReplayStore.test.ts`：CRUD、LRU 淘汰、压缩解压 roundtrip。
- `SpectatorGameStore.test.ts`：写操作抛错；`HAND_REVEAL` 正确更新手牌。
- `Messages.test.ts`：新增消息类型守卫通过。

### 9.2 服务端集成测试

- 启动 `server/index.ts`。
- 创建房间 → 开局 →  spectator 加入 → 验证收到 `SPECTATOR_JOINED` 含完整手牌。
- 当局者出牌后，验证 spectator 收到 `HAND_REVEAL`。
- spectator 关闭连接，验证对局不受影响、房间 `spectatorCount` 减少。

### 9.3 客户端集成测试

- 本地开一局，保存回放，退出到菜单，回放播放，逐回合前进后退跳转，终局结果一致。
- 导出回放文件，清除 IndexedDB，导入文件，再次播放一致。
- 联机对局中观战者视角完整复现骰子动画与手牌。

### 9.4 压力测试

- 用蒙特卡洛跑一局 200+ 回合的极端对局，导出回放，验证文件 < 1MB。
- 回放 4x 速度连续播放 5 分钟，无内存泄漏（`performance.memory` 监控）。

## 10. 验收标准

| # | 功能     | 验收标准                                                                       |
| - | ------ | -------------------------------------------------------------------------- |
| 1 | 联机观战   | 大厅显示至少一个进行中的房间及其「观战」按钮；观战者看到完整棋盘、席位、所有玩家手牌正面；观战者关闭页面后对局继续；观战者无任何可点击操作。     |
| 2 | 对局回放录制 | 本地和联机对局均自动录制；录制内容包含 seed、玩家配置、每回合 TurnResult、卡牌打出、加赛、终局结果；数据可写入 IndexedDB。 |
| 3 | 回放面板   | 主菜单可进入回放列表；终局可保存回放；回放支持逐回合前进/后退、进度条跳转、1x/2x/4x 速度；骰子动画与原始对局一致。             |
| 4 | 回放导出   | 回放可导出为 `.tso.json` 文件；其他玩家导入后可正常播放；导入时校验 schema，错误文件给出明确提示。                |
| 5 | 性能     | 100 回合回放文件 < 500KB；回放播放时 FPS 不低于 55；观战者加入延迟 < 500ms。                       |
