1架构总览：塔罗牌 × 游戏机制

整套塔罗牌 78 张，按游戏功能分为 3 种类型，对应 Kards 的分类思路：

类型Kards 对应游戏机制使用时机说明
指令 Command 指令牌 主动打出，产生效果 己方回合（SelectMode 阶段） 最丰富的类型：操纵骰子、窃取领土、改变倍率等
反制 Counter 反制牌 在特定事件发生时响应 他方回合（抢夺/崩坏/占领时） 防御/反击：减免崩坏损失、抢夺中作弊、取消他人卡牌
恒常 Constant ——（新增） 打出后持续生效 N 回合 己方回合 被动增益光环：每回合额外+1、开发链保护等
设计理由：Kards 的"军队"不适用于本游戏（没有单位），所以去掉。新增"恒常"类型弥补纯粹被动的策略空间，不会让卡牌系统变得太像即时反应游戏。

3行动点（AP）经济

来自你的设定："较强卡消耗行动点更多，一行动点 = 一格领土"

3.1 规则

  • 基础 AP：每回合 0 AP（不免费送）
  • 兑换：1 私有领土 → 1 AP（回合内任意时刻可兑换，不限次数）
  • 效果：消耗的领土进入公共池（保持零和）
  • 使用：AP 仅当回合有效，回合结束清零
  • 限制：私有领土 ≥ 1 时才能兑换（不能把自己换到负数）

3.2 设计意图

这是一个自我平衡的机制：

  • 领先者不想花领土 → 少用牌 → 给落后者追赶空间
  • 落后者可以孤注一掷花领土用强牌翻盘
  • 卡牌效果本身从公共池取领土 → 配合 AP 消耗进入公共池 → 加速终局
  • 全程保持零和

4发放、持有与流程集成

4.1 发放时机

每大轮开始时，所有玩家各自从牌库抽 1 张。

选择"每轮开始"而非"每回合开始"：避免频繁抽牌打断节奏；每轮抽 1 张让手牌逐步积累，策略空间递增。

4.2 手牌上限

3 张。超过上限时必须弃掉 1 张（弃牌进弃牌堆）。

3 张上限在"有策略选择"和"不臃肿"之间平衡。超过上限才弃牌，不是轮轮强制。

4.3 可见性

完全隐藏——只有你自己知道有什么牌。别人只能看到你打出卡牌时的动画。

4.4 用后去向

进入弃牌堆。牌库抽空时，弃牌堆洗回牌库重新使用。
（78 张 ÷ 4 人 ÷ 每轮 1 张 = 约 19 轮才抽完一次，实际对局 32 轮左右，洗回 1~2 次。）

4.5 游戏流程集成

LaunchPhase→ SelectMode→ 🎴 可用指令/恒常牌→ Rolling→ Occupying→ 🛡️ 反制窗口（抢夺/崩坏）→ TurnEnd

指令/恒常牌：在选完模式后、掷骰前使用（给自己上 buff 再掷骰）。
反制牌：当抢夺/崩坏被触发时，所有玩家有短暂响应窗口（约 3~5 秒），可打出反制牌。

⚠️ 没有"随时打断"：反制只在预设的响应窗口有效，不会像即时制卡牌游戏那样随时插入。保持桌游节奏。

5联机同步策略

方面方案
抽牌随机源与掷骰共用 SeededRandom。牌库洗牌在游戏初始化时由服务器种子确定，所有客户端同步洗牌结果。
手牌隐藏服务端权威。客户端只知道自己的手牌内容；他人手牌仅显示数量（"对手有 2 张牌"）。
打出卡牌客户端发送"使用卡牌 X"→ 服务端验证合法性（AP 是否足够、时机是否合法）→ 广播效果给所有客户端。
反制窗口服务端设置超时（5 秒），超时后自动跳过反制机会。保证对局不卡住。

6UI / UX 建议

  • 位置：屏幕底部手牌栏（3 张牌扇形展开），点击放大查看详情。
  • 风格：像素风塔罗牌——深色牌背（星月花纹），正面按花色分色（宝剑蓝、权杖红、圣杯青、金币绿，大牌金色边框）。
  • 动效：抽牌（牌堆飞向手牌）+ 使用（牌翻转 + 对应花色粒子）+ 弃牌（滑出屏幕）。悬浮放大显示详细信息。
  • AP 显示：手牌栏左侧显示"可用 AP：X"，使用领土兑换 AP 的按钮。
