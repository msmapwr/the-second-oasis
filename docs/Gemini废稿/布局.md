收到！作为 **Project ：Regolith**，我们立刻开始敲定《第二绿洲》（The Second Oasis）的**前端网页结构与原型布局（UI Layout Architecture）**。

为了兼顾 PC 端的沉浸观感与移动端的单手操作便捷性，网页布局将采用**响应式 Grid / Flexbox 弹性网格**，整体架构分为五个核心区域：顶栏状态、中央月球看板、四周玩家 HUD、底部控制台以及战局终端日志。

## 2. DOM 组件树结构 (Component Hierarchy)

前端构建时，推荐采用 DOM 与 Canvas 分层叠加的结构：底层为 Canvas 特效/星空，上层为 HTML UI 元素。

```text
app-container (#app)
├── bg-canvas (底层：深空星空与微尘粒子 Canvas)
├── header-hud (顶部状态栏)
│   ├── room-info (房间号 / 局域网状态)
│   ├── crisis-indicator (崩坏系数 x、抢夺触发状态警告)
│   └── system-controls (全屏/音效/帮助)
├── main-viewport (主视口游戏区域)
│   ├── oasis-board-container (中央月球看板 Canvas)
│   │   └── board-overlay-text (公共领土剩余点数居中大字)
│   └── player-hud-grid (4位玩家 HUD 卡片网格)
│       └── player-card (x4，半透明玻片质感卡片)
│           ├── player-badge (头像/阵营色/发射状态标记)
│           ├── territory-counter (私有领土数值)
│           └── combo-indicator (2x / 3x 连续对子极光霓虹灯)
├── battle-log-terminal (战局日志终端，移动端为侧滑/弹窗抽屉)
└── control-console (底部战术操作台)
    ├── mode-selector (【发射/稳健/激进/Pass】战术开关)
    └── dice-stage (骰子 3D/2D 物理翻转与尾迹动画区)

```

## 3. 各模块详细功能与 DOM 职责规范

### ① 顶部状态栏 (`header-hud`)

* **定位**：常驻顶部，高度占视口 $\approx 6\%$。
* **信息展示**：
* **危机指标**：生态崩坏系数（如 `CRISIS MULTIPLIER: x2`，高危时带红色呼吸灯效果）。
* **全局状态**：【抢夺未触发 / 已触发】警报印章。



### ② 月球看板 Canvas 区域 (`oasis-board-container`)

* **定位**：位于屏幕正中央。
* **视觉呈现**：
* 采用 100 格圆环或月球网格图，以高饱度的**绿洲光环 (`#00F5D4`)** 展现公共领土。
* 被占领的区域由玩家专属阵营色填满；因连续 3 次对子事故产生的**荒地 (`#4A5568`)** 呈现无光泽阴影。


* **交互**：Hover 或点击时高亮显示特定玩家的领土占比块。

### ③ 玩家 HUD 卡片 (`player-card`)

* **定位**：四角分布（PC）或上下分列（移动端）。
* **UI 状态机**：
* **未发射**：暗灰色遮罩，显示“待升空”与火焰待命图标。
* **回合中**：卡片边框高亮流动，带有 `CURRENT TURN` 霓虹呼吸灯。
* **对子警告**：触发连击时，右上角浮现闪烁的 `2x` / `3x` 标志。



### ④ 底部控制台 (`control-console`)

* **定位**：常驻底部，高度占视口 $\approx 18\%$。
* **交互响应**：
* 轮到玩家回合时，控制台解除禁用（Disabled）状态，按钮高亮。
* 选择模式（如【激进模式】）后，触发骰子区 `dice-stage` 物理翻转特效，结算完毕后自动清空当前动作。



### ⑤ 战局终端日志 (`battle-log-terminal`)

* **定位**：PC 端右侧固定宽度（占 25% 宽度），移动端为顶部抽屉。
* **渲染规范**：采用等宽字体（Monospace），自动向下滚动至最新日志。发生“崩坏”或“PK”时，该条日志全屏/局部闪烁警示色。
