# 《第二绿洲》网页游戏项目开发计划书
## <i>Project : Regolith</i>
---

## 一、 项目概述

* **项目名称**：《第二绿洲！》（The Second Oasis）
* **游戏类型**：轻度策略回合制网页桌游（单机 AI 对战 / 局域网 WebSocket 联机）
* **开发目标**：基于确立的桌面游戏规则，打造一款无需下载客户端、在浏览器（PC / 移动端）中打开即玩、支持单人与局域网好友对局的 H5 Web 游戏。

---

## 二、 完整游戏规则体系（严格保持原设计）

### 1. 基础设定与参数

* **玩家人数**：2 ~ 4 人
* **公用资源池**：开局公共领土 $= 100$，荒地 $= 0$。
* **玩家状态**：每位玩家初始私有领土 $= 0$，处于“未发射”状态。

---

### 2. 阶段一：发射阶段（发射模式）

所有玩家游戏开始时均需尝试发射，轮流掷 **2 颗六面骰（2d6）**：

* **点数 $\ge 7$（发射成功）**：获得 **2 点**初始私有领土（公共领土 $-2$），下回合进入常规开发阶段。
* **点数 $< 7$（发射失败）**：本回合无事发生，直接顺延至下一位玩家，下回合继续尝试发射。

---

### 3. 阶段二：常规开发阶段

已成功发射的玩家，在轮到自己回合时，**必须且只能**从以下三种模式中选择一种：

| 开发模式 | 投掷规则 | 结算机制 |
| --- | --- | --- |
| **稳健模式** | 掷 **1 颗**骰子 ($n$) | 稳妥获得 $n$ 点领土。绝对不扣分，不触发崩坏。 |
| **激进模式** | 掷 **2 颗**骰子 ($n$) | • **点数 $> 6$**：获得 $n$ 点领土。<br>

<br>• **点数 $\le 6$**：事故！失去 $n$ 点领土（回归公共领土，最低扣至 0）。 |
| **不开发 (Pass)** | **不掷**骰子 | 空过本回合，领土与状态不发生任何改变。 |

#### 额外机制：连续对子（仅在激进模式掷出双数时触发）

* **1 次对子（开发）**：本次获得的领土 **$\times 2$**（当点数<6时，扣的点数也翻二倍）。
* **连续 2 次对子（大开发）**：本次获得的领土 **$\times 3$**（当点数<6时，扣的点数也翻三倍）。
* **连续 3 次对子（过度开发）**：引发核爆级事故！该玩家的私人领土**全部清零**（清零的领土标记为“荒地”，不回归公共领土），该玩家重新回到“发射阶段”！

---

### 4. 阶段三：抢夺与崩坏机制

当玩家 $p$ 结算应得领土 $n$ 时，若 **公共领土 $< n$**，玩家 $p$ 先拿走剩余的所有公共领土（公共领土清零），算出缺口 $m2 = n - \text{残余公共领土}$：

#### A. 抢夺机制（仅触发 1 次）

1. 玩家 $p$ 向除了自己外**私人领土最高**的玩家发起 PK。
2. 双方各掷 1 颗骰子比大小（平局重掷）：
* **胜者**：从败者处夺取 $(m2 - r)$ 点领土。
* **败者**：失去 $m2$ 点领土。
* **归还**：掷 1 颗骰子决定随机数 $r$（若 $r > m2$，则取 $r = m2$），$r$ 点领土**回归公共领土**。


3. 标记“抢夺”已触发。公共领土恢复了 $r$ 点，游戏继续。

#### B. 崩坏机制（“抢夺”触发过后的每一次超额占领）

当公共领土再次为 0，且又有人产生领土缺口 $m2$ 时，引发生态崩坏（初始崩坏系数 $x = 2$）：

1. **其他所有玩家**：各自掷 1 颗骰子，失去“骰子点数”的私人领土（回归公共领土）。
2. **发起崩坏者 $p$**：失去 $(x \cdot m2) - \text{其他玩家扣除的总领土}$ 点私人领土（最低扣至 0）。
3. 结算完成后，崩坏系数增加（$x = x + 1$）。

---

### 5. 终局条件与胜负判断

当发生以下任意情况时，游戏立刻结束：

1. **公共领土为 0**，且结算后**没有任何领土回归**。
2. 发生崩坏后，所有玩家的私人领土均无法继续抵扣。

**胜负判断**：私人领土最多的玩家获得胜利！

## 三、 技术架构与开发方案

```
                   +---------------------------------------+
                   |          前端 UI / 交互层              |
                   | (HTML5 Canvas / Vue3 / Tailwind / Three)|
                   +-------------------+-------------------+
                                       |
                   +-------------------+-------------------+
                               | 状态更新与动作响应
                               v
                   +---------------------------------------+
                   |          核心逻辑引擎 (Logic)         |
                   |      - 状态机控制  - 规则结算        |
                   |      - 概率计算    - 基础AI逻辑      |
                   +-------------------+-------------------+
                                       |
                     +-----------------+-----------------+
                     |                                   |
                     v                                   v
       +---------------------------+       +---------------------------+
       |     【单机模式】 (Local)    |       |   【局域网模式】 (Network)  |
       |  - 本地状态存储            |       |  - WebSocket / Node.js    |
       |  - 前端 JS 模拟 AI 对手    |       |  - 房间管理 / 状态同步    |
       +---------------------------+       +---------------------------+

```

### 1. 技术栈选择

* **前端 (Client)**：Vue 3 / React + TypeScript + Canvas/Phaser.js（用于骰子动画与月球占领可视化动态图表）。
* **单机逻辑引擎**：纯 TypeScript 编写的核心规则状态机（Game Engine），单机模式直接在浏览器端运行。
* **局域网后端 (LAN Server)**：Node.js + Socket.io / WebRTC。
* 房主启动本地微型服务端，其他处于同一局域网（Wi-Fi）的玩家通过输入 IP 或扫码加入房间。



### 2. 核心模块规划

1. **月球看板模块**：动态展示公共领土（100 点的圆环或网格图）与荒地占比。
2. **玩家阵营面板**：展示 4 位玩家的领土数值、发射状态、连续对子计数器（双倍/三倍标志）。
3. **中央操作区**：模式选择控制台（发射/稳健/激进/不开发）、3D/2D 骰子物理投掷动画区。
4. **战局日志栏 (Battle Log)**：清晰打印每一步的结算，特别是“抢夺 PK 过程”与“崩坏数值结算”。

---

## 四、 研发路线图 (Roadmap)

```
[阶段 1: 核心引擎] ──> [阶段 2: 单机 UI & AI] ──> [阶段 3: 局域网联机] ──> [阶段 4: 动效与美化]

```

* **Phase 1：规则逻辑引擎封装**
* 编写纯 JavaScript/TypeScript 的游戏状态机，包含所有骰子结算、对子判定、抢夺与崩坏公式。


* **Phase 2：单机版与基础 UI**
* 构建本地单机模式，实现简单的离线 AI 对手（AI 能根据公共领土剩余量和自己领土选择稳健/激进/Pass）。


* **Phase 3：局域网 WebSocket 同步**
* 加入轻量 Node.js 服务器，实现房间匹配、玩家准备、回合指令同步与断线重连。


* **Phase 4：视觉动效与表现力**
* 加入科幻风 UI、太空/月球主题音效、掷骰子动效以及崩坏时的画面震动与警报特效。
