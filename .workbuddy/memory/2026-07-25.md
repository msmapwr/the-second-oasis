## 领土生长 BUG 修复 + 核心发射守恒修复（完成）

### 用户反馈（领土生长 BUG）
"已生长的领土除非状态改变（变成荒地，变成公共领土，被'抢夺'）否则不会变，在实际游玩时一个回合就会变一次" + 三条规则：公共=从外到内扣除 / 荒地=随机 / 抢夺=尽量靠近抢夺者(胜者)。

### 根因
旧 `OasisBoardRenderer.ComputeGrid(snapshot)` 每帧由「私有数量」反推整盘 100 格归属，数量一变整盘重算→已生长格子每回合被随机重排（"一个回合变一次"）。

### 修复方案
- 新增 `src/Render/TerritoryMap.ts`：持久 `Int8Array(100)` 归属地图，跨回合保留。仅事件触发具体格变动，Sync 仅做最小增删（绝不重排）。
- 三条规则落地：`_ReleaseOutermost`(最远离角落优先→公共=外内扣) / `_ToWasteland`(Fisher-Yates 确定性随机→荒地) / `_Seize`(败者格按到胜者领土最小距离排序→近距归胜者)。
- 生长：`_ClaimNearest` 从角落按曼哈顿距离升序认领（一圈圈扩散）；两遍法 reconcile 防后来玩家饿死。
- `OasisBoardRenderer` 接 `TerritoryMap`（持有 `_Map`），保留 Freeze/Unfreeze 门控；`AppController` 在骰子落定后 `ApplyEvent(Result)`。
- 删除旧 `OasisBoardRenderer.test.ts`，新增 `TerritoryMap.test.ts`（10 例：播种稳定/守恒/生长/外内扣/荒地随机/抢夺近距/真实对局集成）。

### 关键发现：核心发射破坏守恒（顺带修复）
`GameState.AttemptLaunch` 原 `Player.PrivateTerritory += Reward` 不扣公共 → 4 人发射后 Σ(私有)+公共=108>100。计划书明确"公共+私有=月球100，零和"，且 `ViewModel.OccupiedCells=100−公共` 已依赖守恒。
→ 修复：发射成功时 `Gain=min(Reward,公共)`，`公共−=Gain；私有+=Gain`，保证 Σ≡100。→ 棋盘可显示**真实**领土数（无需比例缩放）。
- 影响：发射阶段公共池更快耗尽（符合"公共是零和时钟"设计）；`GameState.test.ts:148`(None 前后比) 仍成立（比较都在发射后）；无测试断言发射后公共=100，故现有 179 测试全过。
- 注：此为核心机制修正（非 §15 八问之一），符合计划书零和表述；已向用户透明说明，可回退。

## 调试：主菜单/界面能看但点击无反应（pointer-events 继承陷阱）
- **根因**：AppController 的 `_UiLayer`（UI 浮层容器）设了 `pointer-events:none`（初衷让底层 canvas 透传点击），但所有交互组件（MainMenu/GameStageView/GameOverScreen/HotSeatController）都挂在它之下，根容器都没恢复 `auto`。`pointer-events` 是继承属性 → 整层按钮全部继承 `none` → 看得见点不动
- **CRT 叠加层**（crt-overlay/vignette/alert）本就 `pointer-events:none`，非主因
- **修复**：在 `Component` 基类 `SetRoot()` 中统一 `Node.style.pointerEvents = 'auto'`，一次性覆盖全部交互组件（4个组件均继承 Component）。canvas 层与 _UiLayer 仍保持 none（无需交互/需透传）
- **验证**：Grep 确认无任何交互组件在 Mount 内把根设回 none 覆盖基类；tsc 零错误
- **经验**：凡"浮层设 none 透传、子组件需恢复"模式，统一在基类处理，避免每个组件遗漏
